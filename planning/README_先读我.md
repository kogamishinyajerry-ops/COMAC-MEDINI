## 交给两个开发条线

A线：沿用已有Medini智能体代码，在受控分支中复制本包01_medini_automation、00_shared、03_contracts和04_sources；将A_开工提示词.md中分隔线后的全文交给开发Agent。

B线：新建或使用独立native-safety-analysis仓库，复制02_native_safety、00_shared、03_contracts和04_sources；使用B_开工提示词.md。不能依赖A线服务才能完成正式求解。

DOCX用于阅读/评审，Markdown用于仓库和Agent上下文。两者内容一致；后续修改需同步。公共契约当前为建议v0.1，首次冻结需两线负责人和安全专家确认。

## 首个验收

A：真实Medini中，在副本创建OR树、保存重开、回读校核；求解接口尚未证实时分开报告。B：自主JSON输入、独立确定性FTA计算、重复事件例题、结构化输出和独立参考校核。两边可以先没有新UI。

首72小时、30/90天和6/12/24个月均为资源/授权/数据到位条件下的相对计划目标；不承诺必然按期达到工程或适航用途。启动会需按实际工时与日历冻结交付日期。A线第10个工作日进行原生接口/半自动/收缩范围分流决策。

## 当前已完成和未完成

已完成：两份规划与开工提示词、共享规则、3个JSON Schema草案、10个有效数学案例、5个负例、标准库参考程序和实测种子验证记录。两份DOCX共27页，已逐页检查版面。

未完成：没有连接用户的Medini/DSH，没有检查用户实际许可证和完整API手册，没有开发A/B正式应用，没有真实业务Gold Case验收，没有适航工具鉴定。规划中的官方API探测、性能和工程试用必须在后续实际环境执行。

本包不含商业软件安装包、私有格式解析器、真实航空数据、可靠性数据库或字体文件。源代码仅为合成小模型参考验证工具，不是生产安全分析产品。

## 运行数学种子

需要Python 3.10或更新版本：

```bash
python 03_contracts/verify_seed_cases.py
```

本次执行15/15通过，详见03_contracts/SEED_VALIDATION_REPORT.md。生产与参考算法必须保持独立；同源实现互相一致不等于正确。

## 关键管理约束

A/B各两位开发者，另设项目/架构与共享质量角色，是对现有六人团队的建议职责划分，不表示已有专项人力。安全专家的人选、每周投入和验收权必须明确；不能让代码产量、一次演示或商业结果一致替代工程验证。

新建10个业务Gold Cases、7开发/3封存是规划目标；不得把本包的10个合成数学案例当作已完成该目标。
