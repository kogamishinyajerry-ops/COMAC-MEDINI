# A线｜Medini 智能体自动化
## 核心规划与实施规格 v1.0

COMAC 二所 · FDE 双项目规划　|　2026-09-21

**项目使命：让现有 Medini 工作流变成可调用、可检查、可恢复的工程能力。**

本项目在合法授权的 ANSYS medini analyze 环境中，实现从需求材料、受控模型变更到分析、结果回读和证据交付的闭环。复用团队已有“PDF需求解析—逻辑理解—故障树生成/重建—软件操作—结果校核”成果；先盘点再加固，不推倒重做。

| 项目要素 | 本版决策 |
| --- | --- |
| 仓库建议名 | medini-agent-automation |
| 第一用户 | 安全性分析工程师、现有 Medini 智能体开发者 |
| 运行位置 | 内网 Windows 许可工作站；DSH 为调用入口 |
| 首个成果 | 在项目副本中完成一个真实故障树闭环并回读校核 |
| 首期周期 | 30天形成试用候选；90天形成受控场景交付包 |
| 成功标准 | 真实 Medini 上可复现的工程作业，不以会话演示为准 |
| 主要边界 | 不重写 Medini 求解器；不自动签发安全结论 |

**与B线的分工。** A线负责商业工具适配、既有工程文件、工作流自动化和实机证据。B线负责不依赖 Medini 的模型、算法及工作台。共用协议与测试输入，不共用唯一的正确性判据。

**文档状态。** 这是可据以开工的建议基线。未取得你们实际安装版本的完整 API 手册、许可证清单和源码，因此下文列出的工具名与路径均为“自建封装接口”，绝不冒充 Medini 官方 API。

# 01｜范围、事实与第一条闭环

## 已核实的技术起点

官方2023技术资料明确列有集成 JavaScript 引擎的 scripting API，可用于自动化和扩展；官方帮助入口也列有 Scripting and API Documentation。[S02][S04] 这足以支持“先探测原生接口”的路线，但不足以确认全部读写、计算和报告操作都能无人值守完成。

Medini 的航空应用涉及多类分析与生命周期工件，不能把“能画故障树”当成整个产品功能覆盖。[S03] 本项目先选你们使用频率最高的一个分析链条，形成可交付自动化，再扩大方法范围。

## 首个业务切片

使用一份经批准的脱敏需求材料和人工建立的参考故障树。Agent提取有来源定位的候选事件及逻辑；工程师确认后，生成变更提案；在Medini项目副本中创建/更新事件与门；保存并重新打开；触发已证实可用的分析；读取模型与结果；输出差异、假设、待审事项及原生工程文件。

**首轮必须分两段验收。** “材料→分析模型”考察专业判断，“已批准模型→Medini执行”考察软件自动化。先用结构化已批准输入打通第二段，避免把文本歧义与接口故障混在一起。

| 30天内必须做 | 明确不纳入首期 |
| --- | --- |
| 能力探测、读模型、项目副本、事件/门创建与更新 | 自动完成完整飞机级 FHA/PSSA/SSA |
| 候选变更预览、人工授权、运行、回读、证据包 | 默认支持全部模块、所有版本与任意大模型 |
| 至少一个批准场景的FTA结果对照 | 依靠自由鼠标点击完成任何未知流程 |
| 已有智能体代码评估与可复用Skill整理 | 绕过许可、改写未公开工程格式、复制专有数据库 |

# 02｜目标架构与接入优先级

## 三个运行位置

**Windows执行端：** Medini、适配器、受控脚本、任务队列、项目副本及本地证据缓存。版本、工作区与许可由执行端显式报告。

**内网管理端：** 可选的任务索引、证据归档和项目权限服务。首期允许本机运行，避免为自动化额外建设庞大平台。

**模型服务端：** 已部署的内网大模型。仅负责理解、提案和解释；不保存官方项目基线，不直接改写Medini工程，不承担精确概率求解。

## 一次调用的路径

工程师 / DSH → 受控工具入口 → 作业协调器 → Medini适配器 → Medini原生项目与分析 → 独立回读校核 → 证据归档 / 人工发布。

| 优先级 | 接入方式 | 进入条件与边界 |
| --- | --- | --- |
| 1 | 官方脚本/API | 有本地文档、示例及成功回读；优先用于语义读写 |
| 2 | 官方导入导出、模板、批处理入口 | 文件格式与调用方式已核实；必须记录映射损失 |
| 3 | 操作系统可访问性/UI控件自动化 | 只处理固定动作；窗口、项目与控件状态校验后执行 |
| 4 | 截图/视觉辅助 | 用于定位和诊断；无法确认状态即暂停并请求接管 |

**文件交换桥的降级方案。** 若脚本只能从Medini内启动，可由批准的脚本读取本地请求文件并输出响应文件，或由人触发一次脚本。是否支持常驻循环、命令行或无界面运行须单独证明。半自动执行可以形成真实阶段成果，但不能标成无人值守。

**DSH解耦。** 先做可测试的CLI/本地服务，再按实际DSH版本验证的MCP或工具扩展接入。业务实现不依赖虚构的插件钩子，不分叉重写Harness。

## 推荐技术组织

Windows协调层建议用Python，便于接口封装、文本处理与本地任务运行；Medini侧脚本使用实际安装版本支持的语言与运行环境。若必须用Java/Eclipse扩展，仅在接口探测证实需要后引入。首期本地持久化可用SQLite，集中协作时再接入团队现有数据库与认证。

**两个负责人。** A1负责原生接口与执行恢复，A2负责工作流、材料处理、回读与评测。你负责业务切片与公共接口裁决；安全专家决定模型、假设与结果是否可接受。开发者不自行批准本人的工程结论。

**资产回收要求。** 现有Medini智能体须提交代码位置、操作方式、示例工程、失败记录、已证明能力及依赖；只有经本次实机回归通过的部分才计入生产候选。

# 04｜自建工具接口契约

以下名称是本项目拟定义的外部接口，不是Ansys官方函数。共同字段与状态规范见《双线协作与公共契约》。

| 工具 | 输入要点 | 输出/约束 |
| --- | --- | --- |
| medini_get_capabilities | worker_id、可选版本要求 | 操作级 verified / partial / unsupported / unverified |
| medini_read_project | 受控project_id、基线版本 | 只读模型快照、原生ID映射、映射损失 |
| medini_prepare_change | 基线、规范化变更、引用证据 | 提案摘要、diff、校验结果、patch_hash |
| medini_apply_change | change_id、有效授权引用 | 在副本实施；绑定基线、补丁和执行版本 |
| medini_run_analysis | 批准模型哈希、配置、能力需求 | job_id；不保证所有分析模式均受支持 |
| medini_get_job | job_id | 状态、阶段耗时、错误、恢复建议 |
| medini_readback | job_id、预期模型哈希 | 重新读取原生模型与结果并比较 |
| medini_export_evidence | 经过校核的job_id | 文件清单、哈希、结果与审批；不等于正式签发 |

## 写入与运行的硬约束

每个写入请求带 expected_baseline_hash、idempotency_key、patch_hash。审批由受信任的人机界面生成，服务端校验授权人、权限、范围与有效期；Agent不能通过传入“approved=true”自批。

同一幂等键与同一载荷返回既有作业；同一键配不同载荷拒绝。共享工作区初期采用单写者排队。副本分析可以自动运行，但从副本升级为正式基线必须再次核验授权与当前版本。

用户路径先解析到获准工作区，不能让模型提供任意磁盘路径。对外执行仅接受结构化参数和审核后的脚本模板，不开放任意eval、任意shell或动态联网安装。

# 05｜作业状态机、故障恢复与证据

## 状态机

received → validated → awaiting_approval → queued → running → readback → verified。

分支状态为 blocked、failed、cancelled、recovery_required。是否正式发布由独立审批流程决定；verified仅表示本次规定的技术校验通过。

**事务边界。** 普通数据库事务不能回滚外部GUI副作用。每次修改使用项目副本、阶段快照和操作日志；发生不确定副作用时先回读再决定继续，不盲目重试。恢复目标是回到可证明的状态，而不是假装支持跨应用ACID事务。

| 故障 | 必须行为 |
| --- | --- |
| 许可不可用、软件未启动 | 进入blocked；保留输入，不消耗无限重试 |
| 项目版本冲突或用户手工修改 | 拒绝写入；重新生成diff和授权 |
| 保存后崩溃/响应超时 | 标记副作用未知；校验副本后再恢复 |
| 弹窗、锁屏、窗口丢失 | 停止相关UI动作；显示接管点，不继续盲点 |
| 任务取消 | 请求停止；实际停止未确认时不得报告已取消 |
| 不支持的门、概率模型或字段 | 明确拒绝/标记损失；不静默简化 |

## 每次作业的证据包

输入原文件与哈希；来源定位；原生工程前后快照；规范化模型；变更提案与授权引用；Medini/适配器/DSH版本；求解配置；原始结果；规范化结果；回读差异；日志与必要截图；人工校核记录；文件清单及校验和。

截图是辅助证据，不是唯一的模型证据。应优先保留结构化回读、原生文件和重开后的状态。审计哈希只能帮助检错/发现篡改，还需要权限隔离、受控存储和备份来保护记录。

# 06｜真实环境探测清单与两周闸门

## 第1—3天的接口事实调查

记录Medini版本/build、许可模块、Windows环境、语言与缩放、安装位置、工作区约束、脚本文档、脚本引擎、导入导出菜单及原有智能体。只读取本地被授权资料与样例，不联网传输真实工程文件。

| 探针 | 最小成功证据 |
| --- | --- |
| 只读 | 返回项目、一个事件及其属性，并与界面/原生导出核对 |
| 创建 | 在副本建立两个基本事件、一个OR门和稳定映射ID |
| 更新 | 修改一个概率/属性，保存重开后仍一致 |
| 分析 | 触发指定模式并取得机器可读结果及配置 |
| 导出 | 生成指定报告/原生项目并核对内容 |
| 恢复 | 至少一次中断后确认项目状态并安全恢复或退出 |

**能力状态必须按操作记录。** 读模型成功，不代表写入或求解成功；脚本运行成功，不代表支持外部无人值守调用；厂商资料存在，不代表用户许可证已包含该能力。

## 第10个工作日的分流决策

**路径A：原生闭环可用。** 固化脚本模板和适配器，进入批量工作流与异常恢复开发。

**路径B：核心读写可用，少量步骤需人触发。** 先交付半自动版，明确人工动作清单和耗时，不用脆弱GUI链条掩盖接口缺口。

**路径C：关键接口不可用。** 将一期范围收缩为“材料整理、导入包生成、结果回读、变更比较”，向软件供应方提交精确接口问题。A线仍可产生价值，但取消未被证明的无人值守承诺；B线按既定契约继续独立研发。

# 08｜评测体系与验收口径

**三层评测分开计分。** 接口执行正确性、数学/模型正确性、Agent专业任务完成率。一个层次通过不能替代另一个层次。

| 维度 | 30—90天建议门槛 | 说明 |
| --- | --- | --- |
| 核心实机流程 | 每个获准流程连续10次运行无静默错误 | 覆盖至少3个模型快照；人工步骤单独计数 |
| 写入一致性 | 事件身份、门逻辑、引用、数值与单位全部相符 | 支持范围内必须100%；布局可分开比较 |
| 故障处置 | 许可失败、冲突、中断、取消、重复请求均有测试 | 不确定副作用必须进入恢复状态 |
| 证据完整性 | 每次受控作业必需工件齐全 | 缺版本/配置/授权/输入哈希则不放行 |
| 工程试点 | 10个Gold Case：建议7个开发、3个封存迁移 | 是本双项目新建目标，不冒用CFD案例数量为已有资产 |
| 提效 | 人工有效操作时间中位数下降30%以上为初始目标 | 与同一批准任务人工流程对比；非当前实测结果 |

10次稳定运行只是试用闸门，不能证明所有任务的统计可靠性。报告必须公布分母、失败、人工接管及不支持项，不能只展示成功作业。

## 迁移验收

专家保管3个未参与开发的同类新任务；适用范围、必需信息、允许的人工确认动作在测试前冻结。测试期间不得针对封存答案修改Skill、模板或代码。出现修复后应使用新的封存任务重测，不能继续称原题为盲测。

## 比較设置

比较前对齐事件身份、逻辑、量纲、任务时间、修复/潜伏假设、概率计算方法、截断阈值和输出指标。不同设置的差异标记为“不可直接比较”。Medini结果是工程参照，不是唯一真值；至少保留手算/穷举的独立小模型。

## 提效与维护的经济账

单次净节省工时＝原人工工时－辅助流程人工工时－摊销的失败恢复与复核工时。月净节省＝获准任务次数×单次净节省－版本维护、用户支持与回归工时。工程师时薪或内部成本由单位另行填入，本计划不假设商业报价。

若一个流程每月几乎不用、接口又高度脆弱，则保留人工步骤比持续维护RPA更合理。优先投入重复频率高、规则明确、可回读校核的流程。

## 开放问题与负责人

Medini版本/许可和自动化授权由A1核实；任务范围/模板由安全专家冻结；数据分级与归档策略由项目负责人协调；DSH接口和离线包由A2验证。未解决项进入风险台账，不能用默认“支持”替代。

# 10｜安全、授权与上线边界

## 受控工具链不自动继承资格

Medini的原有使用方式、自动化脚本、模型转换器和结果检查器形成了新的工具链。是否可以减少独立检查、需要哪些验证或工具鉴定，应由单位质量与适航团队结合具体用途评估。[S05] 采购工具的证书、既往使用经验或内部获奖，均不能直接替代新链路的使用论证。

本线默认是“受监督的工程辅助”。Agent可以提出事件、逻辑、影响范围和工作流；工程师确认失效条件、严酷度、假设、独立性、参数来源和正式结论。对正式基线的写入、批量删除、发布报告和升级适配器实施独立审批。

## 内网安全与供给管理

代码仓库仅存公开或授权脱敏样例；真实项目进入内网受控存储。禁止把PDF、原生工程或日志发送到未批准的外部模型。文档中的任何“忽略规则/执行脚本”等文字均按数据处理，不成为工具指令。

依赖使用固定版本、校验和与软件成分清单；外网开发机只处理合成数据。离线包测试覆盖无网首启、无在线字体/CDN/遥测、凭据脱敏和受控升级。并发作业不突破许可范围；多工作站安排不等于可以共享或绕过授权。

## 主要风险及触发动作

| 风险 | 触发信号 | 对策 |
| --- | --- | --- |
| 原生API覆盖不足 | 第两周仍无核心写入/回读证据 | 缩小流程；保留半自动；向供应方定位问题 |
| 语义映射错位 | ID丢失、单位改变、事件被复制 | 停止发布；回到契约与映射测试 |
| GUI脆弱 | 弹窗/缩放变化即失败 | 减少UI链长度；前后条件校验和人工接管 |
| 专家投入不足 | 模型假设长期无人确认 | 维持研究状态，不用技术测试代替工程验收 |
| 队伍被双线透支 | 长期仅靠一人串行救火 | 冻结新功能；保护B线内核时间；调整范围 |

# 11｜启动会决议与资料索引

## 启动会需要落实的五件事

明确A1/A2与安全技术负责人；锁定一个脱敏业务任务和许可工作站；允许读取对应版本的本地API文档；批准项目副本/日志/证据的存储位置；冻结第一阶段人工授权与结果复核方式。

**开工顺序：** 先读本文件和公共契约，再把本线《开工提示词》交给开发Agent。首次Agent回复应提交环境调查结果与正在执行的首个工作包，不能只生成一份新的计划。

**代码评审清单：** 接口有实证来源；不支持状态可见；无任意执行通道；基线检查与幂等有效；保存重开后有回读；失败不会冒充成功；测试数据与真实数据隔离；工件可以由另一位工程师复现。

**发布签收：** A线负责人签执行能力与限制，安全专家签适用任务与复核规则，质量/配置角色签版本、证据与回退可用性。签收对象是明确版本和明确用途，不是泛化的“Medini自动化全能”。
