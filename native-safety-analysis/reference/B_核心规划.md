# B线｜自主安全分析平台
## 核心规划与实施规格 v1.0

COMAC 二所 · FDE 双项目规划　|　2026-09-21

**项目使命：建设无需 Medini 即可独立完成获准安全分析任务的工程软件。**

本项目以“自制Medini”为对标方向，建设自主数据模型、计算内核、工程工作台和开放接口。长期可以逐项扩大覆盖范围；首期以航空高频工作流为牵引，不以复制商业软件界面或列出大量按钮作为进展。

| 项目要素 | 本版决策 |
| --- | --- |
| 仓库建议名 | native-safety-analysis |
| 第一用户 | 航空系统安全工程师、试点业务专家、FDE开发者 |
| 核心独立性 | 关闭/卸载Medini、断开A线服务后仍可建模和计算 |
| 首个成果 | 结构化静态FTA模型→确定性计算→可复核报告 |
| 30天范围 | FTA基础版、FMEA基础表、追溯、受控变更与离线运行 |
| 90天目标 | 在明确静态模型范围内独立试用并通过迁移验证 |
| 长期方向 | 航空方法闭环、受控MBSA、必要互操作、企业级使用保证 |

**战略边界。** “自主可控”要求掌握数据格式、接口、构建、部署与维护；并不要求每个基础库都从零写。复用开源组件仍需记录许可、版本、来源与验证。B线的正式求解路径不能通过隐藏调用A线/Medini来制造独立性。

**计划性质。** 本文件提供开发基线，不声称已实现产品、完成Medini等价验证或满足适航工具鉴定。所有能力与替代程度按可检验的工作流清单记录。

# 01｜产品边界与替代阶梯

## 把“完美覆盖”变成可验收对象

第1周建立版本化差距矩阵：对标Medini的具体版本、实际使用模块和业务流程；逐项记录功能、输入语义、结果类型、规模、互操作、验证等级和已知限制。无需求和测试定义的“全功能”不能成为合同式承诺。

| 阶梯 | B线达到的状态 | 可作出的声明 |
| --- | --- | --- |
| 研究样机 | 能运行合成小例子 | 能演示，不能替代工程工具 |
| 方法可用 | 受限静态FTA内核与独立验证通过 | 对声明模型范围可独立计算 |
| 工作流可用 | 建模、FMEA/追溯、变更、报告形成闭环 | 对获准任务可进入专家监督试用 |
| 局部替代 | 真实案例、迁移、运维与质量评审通过 | 替代已批准的任务子集 |
| 扩展平台 | 复杂模型、跨团队、互操作逐项验证 | 持续扩大替代范围，公开剩余差距 |

成熟度与功能数分开记录：增加一个菜单不会让研究样机自动达到工程可用；每次升级必须提供相应验证与使用证据。

## 近期价值主张

工程师直接维护可追溯安全模型；Agent提出候选变更；确定性内核计算；结果显示影响路径与依据；模型和报告能在内网离线复现。先把“模型、计算、证据、变更”做牢，再增加界面和方法广度。

官方产品资料表明Medini既有建模与分析，也有追溯、协作和定制能力。[S01] B线差距矩阵因此不能只统计FTA与FMEA两个按钮。

# 02｜能力矩阵与明确排除项

下表是建议开发顺序，并非对Medini全部能力的穷举；具体对标项在实机盘点后补齐。

| 能力域 | 0—3个月 | 3—6个月 | 6—12个月及以后 |
| --- | --- | --- | --- |
| 静态FTA | AND/OR、重复事件、常量、k/n、最小割集、概率 | 重要度/敏感性、规模优化；NOT单独验证 | 扩展概率与分析模式 |
| FMEA/FMES | 表格、稳定ID、关联、批量编辑与来源 | 模板、汇总、层级影响与一致性规则 | 扩展FMECA、必要FMEDA |
| FHA/PSSA/SSA | 对象/字段预留；人工维护基本关联 | 试点工作流、证据索引与检查清单 | 跨层级过程支持与受控报告 |
| 需求/架构 | 轻量组件、功能、失效模式、追溯 | 组件库、变更影响、审查流程 | 更完整模型集成 |
| CCA | 假设与独立性检查项、问题记录 | CMA/ZSA/PRA工件组织 | 经验证的共因概率模型及关联 |
| RBD/MBSA | 不作为一期承诺 | 串并联RBD试点、规则化传播研究 | 故障扩展、受限MBSA与模型检查 |
| 导入导出 | 自主JSON、CSV、结构化证据包 | ReqIF子集、Open-PSA子集 | SysML/外部需求工具的指定映射 |
| 治理与协作 | 单项目基线、审查、审计、离线 | 多用户、权限、发布/回退 | 企业级维护与使用保证材料 |

**一期禁止静默支持。** 动态门、顺序相关故障、修复过程、潜伏/检查间隔、未建模共因相关性、非相干NOT逻辑、任意Weibull/自定义概率表达式，均必须拒绝或标记为不可计算，不能偷偷退化为普通AND/OR。

**领域不混用。** 航空严酷度、发展保证/安全评估字段与汽车ASIL、SPFM/LFM、SOTIF流程分别建Profile。ISO 26262字段不作为航空默认评价规则。PSSA/SSA是工程评估活动及工件组合，不能包装成一个计算按钮。

# 03｜核心架构与模块划分

工程师 / DSH → 统一业务API → 模型与变更服务 → 规则校验 → 计算内核 → 结果与证据 → 人工审查与基线发布。

Agent通过相同业务API工作，不拥有绕开校验直接写数据库的权限；没有LLM连接时，基础建模、FTA、FMEA与报告仍能运行。

| 模块 | 职责 | 独立边界 |
| --- | --- | --- |
| domain | 对象、关系、ID、量纲、约束、模型序列化 | 不依赖前端、LLM或Medini |
| kernel | 布尔语义、BDD、割集、概率与后续算法 | 纯计算输入输出；不处理自然语言 |
| application | 用例、权限、变更、基线、作业状态 | 通过端口调用存储与求解服务 |
| adapters | JSON/CSV/ReqIF/Open-PSA/Medini交换映射 | 显式版本和损失报告 |
| evidence | 来源、验证、审批与文件清单 | 原始工件不可被生成报告覆盖 |
| workbench | 模型、表格、结果、差异、审查 | 与Agent使用同一业务权限 |
| agent_tools | 检索、提案、受控运行与解释 | 只提交候选，不授予自己批准权 |

## 建议技术选择

核心领域层和首版求解器采用Python，以便透明验证和快速迭代；API使用FastAPI等团队能维护的轻量框架；前端建议TypeScript/React。已有项目栈优先复用，具体依赖版本由开工Agent核实兼容与离线可构建性后锁定。

单机采用SQLite，团队版迁移PostgreSQL；迁移脚本和往返测试从一期开始。关系表存对象/关系即可表达初期本体，不先引入图数据库。BDD原生加速、Rust/C++服务或专用图存储仅在测得瓶颈后另立工作包。

# 04｜领域模型：同一事实只定义一次

## 最小对象集合

Project、Baseline、Requirement、Function、Component、FailureMode、FailureCondition、BasicEvent、Gate、FaultTree、FmeaRow、Assumption、AnalysisRun、Evidence、ReviewDecision。

| 对象/关系 | 必需表达 | 常见错误防线 |
| --- | --- | --- |
| Requirement/Function/Component | 稳定ID、版本、来源、分配与实现关系 | 不能用名称当唯一ID |
| BasicEvent | 同一失效事实、概率模型、适用条件与来源 | 重复出现的同一事件仍是同一随机变量 |
| Gate/Occurrence | 门逻辑与子节点引用；视图位置单独保存 | 图形复制不产生新的独立失效事件 |
| FmeaRow | 组件/功能/失效模式、局部/上层影响、控制与证据 | FMEA条目与FTA事件可关联但不强迫一对一 |
| Assumption | 条件、适用范围、提出者、证据、审查状态 | 缺少独立性/任务时间不能靠模型补默认值 |
| Baseline/Run | 模型哈希、配置、求解器版本、结果与工件 | 修改模型后旧结果自动标过期 |

## 三种关系必须区分

“有出处”表示材料中能找到相关信息；“工程师确认”表示有人对解释作判断；“计算/试验验证”表示有验证工件。三者不是同一个validated布尔值。资料直接陈述、Agent推断、专家结论和实测数据分开记录。

将certainty作为说明字段，不把LLM自报置信度当作工程验收准则。Agent可提出新失效模式，但必须标记为推断并说明待确认信息。

## 本体逐步建设

首期用明确的对象、引用与校验规则服务FTA/FMEA闭环；由一线工程师补案例与关系，专家确认术语和传播规则。禁止先做覆盖全部航空知识的庞大本体，再等待业务使用。

# 05｜计算内核的数学边界

## 一期支持的概率语义

**固定概率：** 输入p表示已声明条件/任务上的事件概率，范围0到1，量纲为1。每个不同基本事件默认只有在专家明确接受独立性假设后才能进入独立变量模型。

**恒定失效率、不可修复：** q(t)=1−exp(−λt)，λ单位1/h，t单位h。数值实现使用稳定形式−expm1(−λt)。该q是任务期间失效概率，不自动等同于每飞行小时概率指标、平均不可用度或可修复稳态不可用度。缺单位、缺时间、存在修复/潜伏语义则拒绝此转换。

软件/系统性设计错误不自动分配随机硬件失效率；严酷度、保证等级和合规判断也不由这个公式决定。

## 从结构到精确布尔计算

1. 解析并验证有向无环图、引用与事件身份。
2. 将AND/OR/常量和获准的k/n逻辑编译为规范布尔结构。
3. 用独立基本变量的BDD等算法计算概率，避免把共享事件的不同分支误当独立。
4. 单独生成最小割集；截断时明确incomplete/approximate，不冒充完整结果。

“精确”指在声明布尔模型、概率模型和独立性假设内，不使用稀有事件近似；浮点数仍存在数值误差，必须记录容差和实现版本。

## 不能犯的重复事件错误

设T=(A∧B)∨(A∧C)，pA=0.1、pB=0.2、pC=0.3，A/B/C相互独立。

正确答案：P(T)=0.1×(0.2+0.3−0.2×0.3)=0.044。把两个AND分支错误地当独立，会得到0.0494。界面图形完全正常也可能出现这种数学错误；该例必须成为永久回归用例。

# 06｜内核开发与开源复用策略

## 两种实现，一种独立检查

**生产候选内核：** 先实现可审阅的ROBDD或明确许可的BDD组件，支持稳定变量ID、节点唯一化、计算缓存和资源上限。生产算法不调用Medini。

**独立参考内核：** 对不超过20个基本事件的小模型，用不同实现的穷举真值表及高精度/有理数概率计算验证。参考代码不得直接调用生产内核的布尔编译或结果函数，以免共用同一错误。

**第三方差分：** 可评估SCRAM作为交叉检查器或可替换后端。其仓库提供多类概率风险分析功能，并标示GPL-3.0。[S08] 使用前需确认选定提交的实际能力、构建与许可方案；独立进程并不自动消除许可义务。若它成为生产求解器，不能再作为唯一独立验证者。

## 不做“开源拼装即成熟”的承诺

Open-PSA可作为故障树交换候选，但须验证具体格式版本和实现子集。[S09] xSAP可研究模型检查思路，但官网限定非商业/学术用途，企业集成前必须明确授权，不纳入默认可用依赖。[S13]

## 算法扩展闸门

每新增一种门、概率分布、共因模型或动态分析，必须新增语义规格、独立例题、边界测试、资源测试和报告标签。NOT模型应使用适当的布尔结果表达，不把相干树中的“最小割集”含义原封不动套用。修复、潜伏和顺序相关问题需独立建模，不属于换一个分布公式即可完成。

算法优化必须保持语义与回归结果；必要时同时保留可读参考版本和优化版本。大树按变量顺序、共享结构和资源消耗评估，不能只按节点数量承诺性能。

# 07｜工作台与Agent协作

## 首期四个工作区

| 工作区 | 工程师主要操作 | Agent参与方式 |
| --- | --- | --- |
| 模型/故障树 | 查看、编辑事件与门；引用已有事件 | 提案、结构检查、解释变化 |
| FMEA与追溯 | 表格编辑、关联组件/要求/证据 | 生成候选、检查缺项、建议关系 |
| 分析结果 | 查看顶事件概率、割集、假设与限制 | 解释确定性结果，不自行重算冒充内核 |
| 变更与审查 | 审diff、确认假设、批准或驳回 | 列影响范围与待确认问题 |

界面采用白底、清晰层级，主要操作集中为“生成提案/运行分析”和“审查变更”。证据可展开，默认不刷屏显示脚本、长会话或大量内部工具日志。编辑、运行、审查功能仍需完整可达，不以少按钮牺牲必要操作。

## Agent的五项能力

读取批准资料；提出可追溯候选模型；执行已授权工具；解释结果与差异；在边界之外主动给出缺失信息和阻塞原因。模型提案进入review状态，不直接成为已确认知识。

Agent不能自行批准失效条件分类、独立性与适用性；不能改生产求解器、预期答案、隐藏测试或正式报告签发状态。开发期可以由AI写代码，生产运行期不得允许其自我修改计算内核或绕过发布评审。

## 复现的实际口径

重新调用LLM未必得到相同文字，保存模型名、版本和提示词也不保证完全复现。真正可复现的对象是已批准的结构化模型、参数、求解器/构建与结果。保留Agent候选及可审计的简要理由，不以记录不可见的内部思维过程作为要求。

# 08｜业务API与变更管理

所有接口均为本项目拟定义，不对应Medini原生函数。REST/CLI/MCP只是不同入口，权限与业务校验使用同一套实现。

| 业务能力 | 拟定义操作 | 关键约束 |
| --- | --- | --- |
| 项目与模型 | create_project / import_model / get_model | 输入合法性、版本与来源检查 |
| 候选变更 | propose_change / preview_change | expected_baseline_hash、结构化patch、影响范围 |
| 审查应用 | review_change / apply_change | 受信任用户批准；绑定patch与当前基线 |
| 求解 | validate_model / analyze_fta / get_run | 固定输入、配置、方法与资源限制 |
| FMEA/追溯 | upsert_fmea_draft / link_evidence | 不覆盖已批准事实，保留原始证据 |
| 对照输出 | compare_results / export_bundle | 检查语义与配置是否可比，显示映射损失 |

## 基线与并发

一期单写者＋乐观并发检查；多人版本引入模型级/对象级冲突提示。基线不可就地改写；变更产生新版本；由依赖图把受影响的结果标为stale，旧版证据仍可查看。

首次输入可创建draft模型；正式运行采用该输入的不可变快照。审批记录包含actor、role、change_hash、baseline_hash、scope、时间和理由。审批身份由认证层提供，不信任Agent提交的角色字符串。

## 导入损失分三级

致命损失：逻辑、身份、概率语义缺失，禁止计算。可审查损失：来源/映射关系等不完整，限制用途并要求人工处理。展示差异：坐标/颜色变化等，可与语义验证分开。不可解析的原始扩展可以保留为opaque数据，但不得宣称已理解或完整兼容。

# 09｜独立验证、精度与性能

## 验证金字塔

基础Schema检查 → 领域语义检查 → 代数与手算用例 → 小模型穷举 → 随机/变形测试 → 第三方差分 → 专家Gold Case → 封存迁移任务 → 上线用途评审。

| 测试类别 | 必测内容 | 初始闸门 |
| --- | --- | --- |
| 布尔语义 | AND/OR、吸收、重复事件、共享子图、k/n、常量 | 全部声明支持的例子通过 |
| 非法输入 | 悬空引用、循环、ID冲突、概率越界、未知门/分布 | 显式错误，绝不返回貌似有效结果 |
| 数值 | 零/一、极小概率、长表达式、指数模型量纲 | 与有理数或高精度参考逐项比较 |
| 变形测试 | 交换结合、等价重写、单调性、重复项消除 | 不改变应不变结果；有反例即阻止发布 |
| 状态与安全 | 并发冲突、越权、旧审批、输入注入、异常中止 | 服务端阻断；保留证据 |
| 独立运行 | 无Medini、无A线、无LLM、无外网 | 核心建模/计算/导出仍可用 |

## 精度目标是待验证的规格

对首期明确覆盖的概率区间和模型类别，以有理数/高精度结果为参照，建议双精度概率容差初始为相对1e−12＋绝对1e−30；第两周由算法负责人和验证者按极小概率/抵消测试冻结。不能用宽松绝对误差把关键稀有事件“比较成相同”。

保留原始精度数据，显示舍入不改变存储结果；跨平台按数值与语义容差比较，不要求PDF文件或浮点末位逐字节相同。

## 性能边界

首期基准按小/中/压力模型分档，记录变量数、门数、共享结构、BDD节点数、最小割集数量、耗时与峰值内存。建议设置单作业60秒初始超时和可配置内存上限；超限返回resource_limit，不输出截断后冒充精确值的结果。具体交互目标在目标Windows机实测后冻结。

# 12｜航空过程、使用保证与知识产权

## 标准版本作为配置，不作为宣传标签

航空项目需记录适用审定基础与采用的标准版本。SAE已有ARP4754B、ARP4761A相关资料；FAA AC 20-174涉及ARP4754A。[S06][S07] 不因此推断你们型号已经采用某一新版。主管安全/适航团队应确认版本、裁剪与证据要求。

工具可支持FHA/PSSA/SSA工件组织，但并不凭软件自动完成安全工程判断。DO-178C针对机载软件相关保证活动；地面安全分析工具不能一概按机载软件等级开发。是否涉及DO-330及何种要求，须按具体用途、输出依赖及被替代的验证活动评估，不能在本计划中预设TQL。[S05]

## 三档使用方式

研究用途：只用合成或批准脱敏数据，报告水印说明不用于正式结论。受监督工程辅助：定义每类输出的独立检查方法和检查人；“有人点确认”本身不等于充分验证。批准用途：基于明确版本、范围、使用环境、验证证据和质量/适航评审放行。

## 从第一天保留的保证材料

工具用途与边界；工具运行需求；需求—实现—测试追溯；算法规格；测试预期结果及独立来源；配置与构建标识；问题报告；验证结果；操作限制；发布/变更影响记录。后续是否形成正式工具鉴定计划与总结，由项目过程确定。

## 合法复用边界

采用公开方法与合法授权资料自主实现；不复制Medini代码、界面资源或受限可靠性数据库，不绕过许可证，不默认逆向私有格式被允许。脱敏不自动赋予对外使用权。对SCRAM等开源依赖，建立许可证清单和分发审查；对xSAP等受限软件先取得授权。[S08][S13]

# 13｜团队、经济性与核心风险

## 两名开发者的真实分工

B1负责领域语义、计算内核与验证规格；B2负责工作台、API、数据与Agent入口。核心数学代码需要另一位具备相应能力的人审查；不能只让生成代码的同一Agent生成“参考答案”并宣布通过。人员不足时由跨线开发者交叉验证并由专家裁决，必要时外部增援。

由你把控范围、架构和复用资产；共享协调/质量角色维护项目流程；安全专家拥有工程语义与验收决策权。具体个人任命在启动会确认，不能将共享专家当作已经到位的全职成员。

## AI改变哪部分成本

本计划将AI主要用于样板代码、界面、适配、测试候选、文档和重构提速。核心算法验证、案例判断、数据授权、配置管理和真实使用保证仍单独排期。代码产量不计作业务价值，采用获准任务覆盖、人工工时和问题关闭质量评估。

| 风险 | 最早可观察信号 | 处理 |
| --- | --- | --- |
| 伪独立 | 求解偷偷经A线调用Medini | 架构测试、网络隔离、无Medini验收 |
| 伪正确 | 仅与一个商业结果相同 | 高精度穷举、变形测试、专家新题 |
| 伪完整 | 菜单齐但算法/语义为空 | 工作流级矩阵；禁止空实现报成功 |
| 范围膨胀 | 首月同时造图平台、SysML、全部分析法 | 只交静态闭环；其他列后续工作包 |
| 关键人风险 | 只有B1理解内核 | 可读规格、交叉评审、复现训练 |
| 持续维护不足 | 升级无回归、离线依赖失效 | 锁版本、保留构建包与支持责任 |

**成果归属口径。** 业务模型、规则、证据与开发方法成为二所资产；对基础开源代码保留原许可与署名。自主控制的范围应逐层声明，不把“可本地运行”等同于全部知识产权归己。

# 14｜上线清单与来源索引

## 独立替代的最终检查

关闭Medini与A线后，B线能读取自己的模型并计算；普通工程师能安装和操作；另一个验证者能从输入独立复核；工程假设与适用范围已审查；损失/未知项可见；版本与基线可恢复；维护负责人明确；获准用途有书面记录。
